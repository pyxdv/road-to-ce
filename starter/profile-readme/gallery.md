# โปรไฟล์ตัวอย่างของจริง

หน้านี้รวมโปรไฟล์ GitHub ที่ออกแบบไว้ดี แยกตามสไตล์ ใช้ดูเป็นตัวอย่างก่อนเลือกว่า
จะทำหน้าของตัวเองแนวไหน แต่ละสไตล์มีเทมเพลตพร้อมคัดลอกอยู่ในโฟลเดอร์ [`styles/`](styles/)

> **อ่านตรงนี้ก่อน** โปรไฟล์เหล่านี้เป็นของนักพัฒนาที่ทำงานมาแล้วหลายปี
> สิ่งที่นำมาใช้ได้คือ **โครงสร้างและวิธีจัดข้อมูล** ไม่ใช่เนื้อหา
> การคัดลอกข้อความแนะนำตัวของคนอื่นมาทั้งดุ้นเป็นเรื่องที่ดูออกง่ายมาก และเสียหายกว่าไม่ทำ
>
> โปรไฟล์เปลี่ยนได้ตลอดเวลา สิ่งที่เห็นวันที่เปิดดูอาจไม่ตรงกับคำอธิบายด้านล่างแล้ว

---

## 1. Minimalist & Systems Engineer

เรียบ ชัดเจน ไม่มีของตกแต่ง เน้นบอกว่า **สร้างอะไรไว้บ้าง** และ **สนใจระบบด้านไหน**
เหมาะกับคนที่ชอบความกระชับ และคนที่คิดว่าของตกแต่งเยอะ ๆ ทำให้เนื้อหาหาย

| โปรไฟล์ | ใคร | จุดที่น่าดู |
|---|---|---|
| [sindresorhus](https://github.com/sindresorhus) | นักพัฒนา open source เต็มเวลา | ไม่ใช้ widget ใด ๆ ใช้ Markdown ล้วน จัดกลุ่ม repository ที่เป็นผลงานเด่นให้หาเจอทันที แนวคิดคือ "ผลงานพูดแทนตัวเอง" |
| [muesli](https://github.com/muesli) | ผู้พัฒนาเครื่องมือสาย Go และ CLI | วางหน้าให้มีกลิ่นอาย command line สื่อสายงาน systems / backend ได้ชัดโดยไม่ต้องเขียนว่าตัวเองถนัดอะไร |

**ใช้กับเราได้ตั้งแต่ปี 1:** ตัดทุกบรรทัดที่ไม่ให้ข้อมูลออก เหลือเฉพาะชื่อ สิ่งที่กำลังทำ และลิงก์ผลงาน
→ เทมเพลต [`styles/minimalist.md`](styles/minimalist.md) และแบบ command line [`styles/terminal.md`](styles/terminal.md)

## 2. Learn in Public & Student Story — แนะนำสำหรับปี 1 มากที่สุด

เล่าเส้นทางการเรียนรู้ว่า **กำลังเรียนอะไร ฝึกทำอะไร และจะไปทางไหน**
เป็นสไตล์เดียวที่ใช้ได้ทันทีตั้งแต่วันที่ยังไม่มีผลงาน เพราะสิ่งที่แสดงคือทิศทาง ไม่ใช่จำนวนงาน

| โปรไฟล์ | ใคร | จุดที่น่าดู |
|---|---|---|
| [sw-yx](https://github.com/sw-yx) | Shawn Wang ผู้เขียน The Coding Career Handbook | ผู้ริเริ่มแนวคิด *Learn in Public* — เขียนสิ่งที่กำลังค้นคว้าออกมาให้คนอื่นเห็นระหว่างทาง ไม่รอให้เก่งก่อนแล้วค่อยเขียน |
| [rishavanand](https://github.com/rishavanand) | นักพัฒนา | โครงเป็น bullet มาตรฐานที่อ่านจบใน 10 วินาที: กำลังทำอะไร · กำลังเรียนอะไร · ถามฉันเรื่องอะไรได้ · ติดต่อยังไง |

**ทำไมเหมาะกับปี 1:** คนอ่านโปรไฟล์ของนักศึกษาปี 1 รู้อยู่แล้วว่าเราอยู่ปี 1
สิ่งที่เขาดูคือ *เรียนรู้ต่อเนื่องไหม* ไม่ใช่ *เก่งแค่ไหนแล้ว*
→ เทมเพลต [`styles/learn-in-public.md`](styles/learn-in-public.md)

## 3. Interactive & Visual Tech Stack

ใช้ badge โลโก้เครื่องมือ และการ์ดสถิติ ทำให้หน้าดูมีมิติและทันสมัย
สวยเร็ว แต่ **ควบคุมยากที่สุด** เพราะของประดับล้นเมื่อไรเนื้อหาจะหายไปทันที

| โปรไฟล์ | ใคร | จุดที่น่าดู |
|---|---|---|
| [anuraghazra](https://github.com/anuraghazra) | ผู้สร้าง `github-readme-stats` | การ์ดสถิติและการ์ดสรุปภาษาที่ใช้ ต้นทางของการ์ดที่เห็นกันทั่วไปในโปรไฟล์คนอื่น |
| [abhisheknaiidu](https://github.com/abhisheknaiidu) | ผู้รวบรวม `awesome-github-profile-readme` | แบนเนอร์หัวเรื่องแบบเคลื่อนไหว (SVG) และการจัดผลงานเป็นตารางที่ยังอ่านง่ายอยู่ |

**ข้อควรระวัง:** ใส่โลโก้เฉพาะเครื่องมือที่ **ใช้เป็นจริง** และการ์ดสถิติของนักศึกษาปี 1
ยังแทบไม่มีข้อมูลให้แสดง อ่านข้อจำกัดทั้งหมดก่อนใช้ที่ [`styles/visual.md`](styles/visual.md)
→ เทมเพลต [`styles/visual.md`](styles/visual.md)

## 4. นักพัฒนาไทยที่ทำงานระดับสากล

ดูไว้เป็นภาพว่าเส้นทางนี้ไปได้ไกลแค่ไหน และคนที่เริ่มจากจุดเดียวกับเราเขาสะสมงานกันอย่างไร

| โปรไฟล์ | ใคร | จุดที่น่าดู |
|---|---|---|
| [dtinth](https://github.com/dtinth) | Thai Pangsakulyanont | ประวัติการสร้างเครื่องมือ open source ต่อเนื่องยาวนาน และการทดลองเขียนโค้ดแก้ปัญหาจริงที่เจอเอง |
| [heypoom](https://github.com/heypoom) | Poomparin Mano | หน้าที่สะอาดและทันสมัย เห็นเส้นทางตั้งแต่งานสมัยเรียนจนถึงงานระดับ production |

**สิ่งที่ควรสังเกต:** ทั้งสองคนไม่ได้เริ่มจากโปรไฟล์สวย แต่เริ่มจากการทำงานเล็ก ๆ ให้เสร็จแล้ว
เขียนอธิบายมันได้ ทำแบบนั้นซ้ำ ๆ หลายปี โปรไฟล์จึงตามมาเอง
